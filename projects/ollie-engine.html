OllieEngine

My own game engine, built from scratch in C++ on top of OpenGL. It's a personal project to really understand what goes on underneath the engines I use every day: the game loop, the render pipeline, the scene graph and all the maths that holds it together.

Role Solo Developer
Language C++17
Graphics OpenGL 3.3 Core
Libraries GLFW, GLEW, GLM

Core Features

What the engine can do so far.

  • Engine library and game executable kept separate, with games plugging in through an Application interface
  • Game loop with delta time, plus keyboard and mouse input handled through GLFW callbacks
  • Render queue of draw commands, with meshes built from a data-driven vertex layout and shaders that report compile errors
  • Scene graph of GameObjects with parent/child transforms composed through the hierarchy
  • Component system with its own type IDs instead of C++ RTTI
  • Quaternion-based rotation and a free-fly camera with mouse look and WASD movement

Design

The engine is built as a library under its own eng namespace, and the sample game is a separate executable that links against it. Game code only ever talks to the engine through the Application interface, the scene and its components, so the two stay cleanly separated.

Behaviour lives in components rather than deep class hierarchies, so a camera is just a GameObject with a camera component and a player controller attached.

Development Challenges

Moving rotation from Euler angles to quaternions meant rewriting the camera's mouse look: yaw around the world's up axis, pitch around the camera's own right axis, then normalise so floating-point drift doesn't build up.

Some bugs only show up later. The index buffer was being sized with sizeof(float) instead of sizeof(uint32_t) and only worked because both are 4 bytes, and the mouse look was scaled by delta time, so it turned faster or slower depending on the frame rate.

The Frame Loop

What the engine does every frame.

  1. Poll window and input events from GLFW
  2. Work out delta time since the last frame
  3. Update the game and scene, with components submitting draw commands
  4. Build the view and projection matrices from the main camera
  5. Draw everything in the render queue, then swap buffers
